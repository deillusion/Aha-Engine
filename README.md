# Varina-Grounded Creative Agent

Varina 是一个以真实工作区文档与代码资料为事实锚点的对话式创作智能体（Agent）。它借用现代 Coding Agent 的工具执行循环与安全防护范式，但专为**游戏机制设计、产品规则系统、数值边界推演、世界观规则体系与复杂架构权衡**量身定制。

系统已彻底从早期“提交固定问题、顺序跑完多轮会议、Chair 唯一裁决”的僵化 Workflow，升级为**长驻交互式会话 Agent**：平时保持低延迟日常对话与工作区资料检索，仅在用户面临复杂机制冲突或架构困境时，受控调用内嵌的 **ExploreDesign（Varina 引擎）** 展开 8 席位多视角发散推演，最终交付**可复核事实账本、原子观点板与 2–3 套互不从属的正交机制装配方案**。

### 1. 双层 Agent 运行循环
- **主对话层（Bounded Tool Loop）**：普通问答、代码/文档梳理、局部方案调整直接在对话流中低延迟响应。每一轮对话最多进行有限次数的 `模型 → 工具 → 结果 → 模型` 迭代。每个 `tool_call_id` 严格执行一次并与结果配对，无伪装完成的静默失败。
- **重型推演层（ExploreDesign）**：作为主 Agent 治理下的重型工具，专门负责在遇到复杂设计分歧、规则冲突或开放难题时展开多席位推演。
- **项目初始化（`/init`）**：主 Agent 读取少量高权威资料，生成工作区根目录的 `VARINA.md`。它是项目的 Level-1 系统心智模型与领域本体，记录身份边界、高层运行方式、核心概念、负面护栏和验证路径，而不是开发指南或文件清单；重复输入 `/init` 会自动备份旧版本并重新生成。
- **忠实委派协议**：后续每轮自动加载 `VARINA.md`。调用 ExploreDesign 时，运行时逐字携带用户原始请求，并把用户约束、已读原文片段与 Agent 假设分栏传递；无法追溯到用户原话的“硬约束”会被本地拒绝，项目资料则由运行时按已读文件与行号重新读取、原样拼接，主 Agent 不能用自由摘要冒充已核查事实。

### 2. 工作区安全与写入意图硬门控
- **路径与文件安全隔离**：所有文件操作基于词法路径与 `realpath` 进行双重校验，严禁 `..`、符号链接及 Windows Junction 越界访问；非 UTF-8 二进制与超大文件默认拦截。工作区文档内容严格视为不可信数据，其中出现的任何提示词注入（如“忽略规则”、“调用写文件工具”）均不会改变工具执行权限。
- **写入意图门控（Write Intent Gating）**：只有当当前用户消息包含明确的落盘意图（如“保存”、“写入”、“修改文件”、“输出到文件”）时，主 Agent 的 `Edit` / `Write` 工具才会被本地门控放行，避免大模型“擅自做主”修改本地项目。
- **无 Git 依赖的原子备份与版本恢复**：
  - 写入前执行二次 SHA-256 Hash 陈旧检查，防止外部并发修改被意外覆盖；
  - 覆盖文件前自动在 `<workspace>/.aha/backups/<backup-id>/` 保存原始字节镜像；
  - 目标文件写入均采用临时文件 + rename 原子替换；
  - 内置 `ListBackups` 与 `RestoreBackup` 工具，在完全脱离 Git 的轻量环境下也能随时查看与秒级回滚历史版本。

### 3. 工业级上下文体积闸门 (Tool Result Budget)
对标 Claude Code 工业标准，按字符严格计量，彻底解决检索代码库时大文件打爆上下文与消耗巨额 Token 的问题：
- **单行限宽**：Grep 命中行若超过 500 字符，自动截断并在结果中标注 `line_chars` 与 `truncated: true`，防止单行超大数据文件瞬间撑爆对话。
- **单条结果体积上限**：`Grep` 单条上限 20,000 字符，其余工具上限 50,000 字符。超限时**自动落盘而非截断丢弃**，对话上下文只保留 `<persisted-output>` 标记、2,000 字符预览、完整字符数与 `persisted_path`。模型如需阅读细节，可随时通过 `Read` 按路径精准调取。
- **单轮聚合预算闸门**：单轮对话内所有工具结果合计上限为 200,000 字符。若多工具命中总量超标，系统将从体积最大的结果开始逐个降级落盘，直至整体回到预算安全线内。
- **干净隔离**：落盘文件写入工作区 `.varina/tool-results/` 目录下，该目录被 `listFiles` 默认跳过，既杜绝下一次检索时的递归污染，又确保模型具备读取权限。

### 4. 分级重试与网络韧性 (Retry Policy)
- **HTTP 状态码白名单**：仅对网络闪断与服务端限流（408 / 409 / 429 / 5xx）进行阶梯式重试。
- **400 致命错误零重试**：对于参数非法、上下文溢出等客户端错误（400），坚决一次性失败终止，绝不重传数十兆的大包体。
- **智能格式修复闭环**：仅在本地 JSON 解析或 Schema 契约校验失败时，才向模型追加带有错误细节的“格式修复提示”进行重试。

### 5. ExploreDesign 8 席位深度推演机制
- **4×2 席位并行发散**：每轮并发调度 8 个创意席位，每个席位注入独立模型配置与 3 张版本化认知算子卡（Cognitive Operators，如反向博弈、极端约束、跨界借喻、失效假设等），激发多视角思维碰撞。
- **同轮逐字一致的冻结前缀 (Frozen Common Prefix)**：同轮全部 8 个席位共享逐字一致的公共前缀（包含设计问题、硬约束、已确认事实账本、当前观点板及 Working Memory 快照 Hash），席位特异算子追加于末尾。极大发挥主流大模型供应商的 **Prompt Cache** 机制，成倍降低推演成本与首 Token 延迟。
- **席位响应规范化（normalizeSeatResponse）**：运行时自动校准并规整席位输出的贡献编号（`C1..C3`）与核验请求编号（`V1..V2`），消除多模型幻觉与 ID 错位。
- **严密的事实验真闭环 (Grounded Fact Verification)**：
  - 席位只负责抽象机制发散与提出假设，不直接接触文件正文；
  - `Grounder` 从已加载资料中核查假设，并可发起结构化加载请求；
  - `EvidenceVerifier` 物理重读源码与文档，校验文件路径、内容 Hash、行号范围与代码片段。验真失败的事实显式降级为 `unknown` 或 `stale`，确保观点绝不建立在失实代码之上。
- **严格去重与观点结晶 (Dedup)**：对候选机制逐项严格执行 ADD / MERGE / DROP；失败时保底为全量 ADD，绝不静默丢弃已付费成果。
- **动态早停与正交装配 (Assembly)**：最多执行 5 轮推演；当连续两轮新增观点为 0（ADD=0, MERGE=0）且无阻断未知项时自动早停收敛。终局 Assembly 仅基于活跃 Point ID 装配 2–3 套互不从属、权衡清晰的正交机制方案（核心机制、防守补丁、固有代价）。**不设 Chair 独裁，不跑 R6，不挑选唯一赢家**。
- **门控策略**：首次机制难题自动触发，后续追问复用已有观点板与事实账本；再次发散需用户确认，或通过 `/varina` (兼容 `/aha`) 指令及界面开关直接放行。

### 6. 物理隔离存储与状态恢复 (Session Store)
- **物理分流隔离**：真实运行会话存储于 `.varina/data/sessions/live/`，离线模拟演练存储于 `.varina/data/sessions/mock/`。支持按模式过滤、单会话删除与一键清空模拟记录。
- **历史记录平滑迁移**：启动时自动将根目录的遗留会话文件迁移至对应的 `live/` 或 `mock/` 目录。
- **崩溃恢复与密钥纯净**：会话状态与推演 Checkpoint 均通过临时文件 + rename 原子落盘；进程异常终止后重启时，未完成会话自动标记为 `interrupted`，绝不静默重复计费；持久化文件与审计日志中严格剥离 API Key。

## 快速上手

### 环境要求
- **Node.js**：`>= 22.0.0`
- **零 npm 运行时依赖**（无需 `npm install` 任何第三方包）。

---

### 1. Web 现代化工作台（推荐）

启动本地可视化服务：

```bash
npm start
```

启动后在浏览器打开 **<http://127.0.0.1:27333>**。

- **创建会话**：点击「＋ 新会话」，在目录浏览器中选择你的游戏/产品工作区根目录，并选择「真实模型」或「离线模拟」模式。
- **模型配置**：点击左下角「模型设置」或输入框上方的模型按钮，即可打开配置弹窗，配置 API Key、选用主流供应商预设、执行连通性测试与模型探测。
- **Aha 探索控制**：输入框左侧配有 **✦ Aha 探索** 药丸开关，可随时一键开启或关闭深度机制推演。
- **会话管理**：侧边栏支持「真实会话」与「模拟推演」双 Tab 切换查看，支持单条删除或一键清空模拟记录。

#### 自定义开放目录
若想限制工作台文件浏览器的访问范围，可通过环境变量指定：

```dotenv
VARINA_WORKSPACE_ROOT=D:/my-creative-project
PORT=27333
```

---

### 2. 命令行交互 CLI

启动交互式长驻会话：

```bash
# 启动交互式会话（默认进入多轮对话）
npm run run -- --workspace D:/my-creative-project

# 继续已有会话（复用观点板与事实账本）
npm run run -- --session session-xxxx-xxxx

# 离线模拟演示（不调用外部模型，不消耗 Token）
npm run demo -- --prompt "设计一个十分钟内持续产生资源取舍的合作机制"
```

CLI 会话支持直接对话、自动工具调用展示，输入 `/exit` 或 `/quit` 安全退出。

首次进入一个项目时可输入 `/init` 生成 `VARINA.md`；项目的稳定定义或架构发生变化后，再输入一次 `/init` 即可重新扫描并安全更新。旧版本会自动备份，普通资料变化不需要频繁初始化，细节仍由 Agent 按当前任务读取原文件。

### 3. 作为 MCP 工具接入 (Claude Code / Cursor)

Aha 提供标准 stdio MCP（Model Context Protocol）服务，协议版本兼容 `2024-11-05`。可让 Claude Code、Cursor、Claude Desktop 将 Aha 作为强大的机制与架构共创工具调用。

#### 启动 MCP 服务

```bash
npm run mcp
```

#### MCP 工具说明
- `varina_chat`（**主推工具**）：对话式接入，第一次调用不传 `session_id`，后续传回响应里的 ID 即可继续同一会话，自动共享与演进观点板与事实账本。
- `varina_design_architecture`（**兼容别名**）：为旧版客户端保留的兼容别名，内部已升级走全新 Agent 引擎，不再调用 Chair 或 R6。

#### 接入配置示例
在客户端的 MCP 配置文件（如 `claude_desktop_config.json` 或 Cursor MCP 配置）中添加：

```json
{
  "mcpServers": {
    "aha": {
      "command": "node",
      "args": ["C:/absolute/path/to/prototype/mcp.mjs"],
      "env": {
        "VARINA_WORKSPACE_ROOT": "D:/my-creative-project"
      }
    }
  }
}
```

#### MCP 专用管理面板
系统还附带独立的 MCP 管理界面，方便单独调试 MCP 参数、配置模型与查看工具调用审计：

```bash
npm run mcp:ui
```
打开 <http://127.0.0.1:4318> 即可访问。

## Web 工作台功能详览

现代化 Web 界面采用纯原生架构构建（零第三方打包含袱），交互体验轻盈顺滑：

### 1. 现代化对话与思维链
- **轻量零依赖 Markdown 引擎**：原生支持流式输出渲染、代码块语法高亮排版与**一键复制代码**功能。
- **思维过程（Thinking Process）展开**：主 Agent 的各轮思考过程独立卡片展示，实时追踪并展示单轮思考耗时（`duration_ms`）。
- **平滑悬浮球**：长对话中自动呈现「回到底部」浮标，支持一键平滑滚动回到底部。

### 2. ✦ Aha 探索快捷开关
- 输入框左下方提供常驻胶囊开关：
  - **开启状态**：遇到机制难题、架构冲突或数值边界时，Agent 可自动展开 8 席位深度推演；
  - **关闭状态**：强制 Agent 仅进行常规低延迟对话分析与代码/文件工具调用，绝不调用 ExploreDesign。

### 3. 大模型选型与推演规则配置面板
- **主对话模型一键切换**：快速指定全局默认对话与工具调度模型。
- **主流服务商预设一键填入**：内置 DeepSeek、Gemini（原生协议）、OpenAI、Claude、SiliconFlow（硅基流动）、Qwen（通义千问）、Ollama 本地模型等常用端点模版。
- **在线连通性测试与模型探测**：支持单模型「⚡ 测试连通性」和「🔍 探测模型」（自动发现该端点支持的在线模型列表）。
- **多角色与 8 席位细粒度调度**：
  - 支持分别指定 Chair（整理）、Dedup（结晶）、Dealer（发牌）、Grounder（验真）、Assembly（装配）的担当模型；
  - 支持为 8 个创意席位单独指派不同模型，实现真正的**异构大模型混合推演**。

### 4. 嵌入式 4×2 席位推演看板 (Aha Workbench)
当触发 ExploreDesign 时，对话消息下方直接展开原生推演工作台（无需切页）：
- **4×2 席位发散看板**：直观展示 8 个席位的分配模型、本轮抽取的 3 张认知算子卡片、席位思考过程折叠以及提炼出的原子机制贡献（高亮失效边界）。
- **收敛统计徽标**：每轮清晰显示 `+新增`、`合并`、`淘汰` 以及代码事实验真数量。
- **多视角深度复核 Tab**：
  - **装配方案**：展示正交机制装配卡片（核心机制、防守补丁、固有代价）；
  - **事实账本**：展示全部核验事实（`confirmed` / `contradicted` / `unknown` / `stale`）及引用文件行号；
  - **观点板**：展示已沉淀的原子观点、修订版本号与失效边界；
  - **淘汰方向**：记录被去重淘汰的重复方向与明确理由。

## 核心配置与环境变量

项目根目录的配置优先级为：`环境变量 (.env)` > `本地配置 (config.local.json)` > `默认配置 (config.example.json)`。

### 环境变量 (`.env`) 示例

```dotenv
# 工作区根目录（限制文件浏览范围）
VARINA_WORKSPACE_ROOT=C:/Projects/MyGame

# Web 服务端口（默认 27333）
PORT=27333

# 模型 API 密钥（可配置多个服务商）
DEEPSEEK_API_KEY=sk-xxxx
GEMINI_API_KEY=AIzaxxxx
OPENAI_API_KEY=sk-xxxx
ANTHROPIC_API_KEY=sk-ant-xxxx
SILICONFLOW_API_KEY=sk-xxxx
```

在 Web 界面中录入的密钥保存在本地 `config.local.json` 中，已被 `.gitignore` 排除，绝不会被意外提交。

## 数据持久化结构

所有工作区元数据、推演数据与会话审计均统一收纳在 `.varina/` 目录下（被 `listFiles` / `grep` 默认过滤，避免污染模型检索上下文）：

```text
<workspace>/
└── .varina/                         # Varina 元数据与持久化目录（Grep / Glob 默认完全跳过）
    ├── backups/                     # 覆盖写前自动备份的原始文件
    │   └── <backup-id>/<path>
    ├── tool-results/                # 超出体积预算的超大工具结果落盘
    │   └── <session-id>-<turn>-<iteration>-<tool-id>.json
    └── data/                        # 运行与会话数据
        ├── sessions/                # 对话会话审计 JSON
        │   ├── live/                # 真实模型运行产生的会话审计 JSON
        │   │   └── session-<uuid>.json
        │   └── mock/                # 离线模拟演练产生的会话审计 JSON
        │       └── session-<uuid>.json
        ├── runs/                    # 历史实验运行记录
        │   ├── live/
        │   └── mock/
        ├── checks/                  # 模型检查记录
        └── diagnostics/             # 诊断报告输出
```

## 自动化测试与验证

项目内置 101 项高覆盖率自动化测试，全部采用本地模拟运行，**不依赖外部网络与真实 API Key**：

```bash
# 运行完整测试套件
npm test
```

测试覆盖的关键机制包括：
- **安全与边界**：工作区路径越界、符号链接穿透、CRLF/BOM 规范化、二次 Hash 陈旧写入拦截、覆盖前原子备份与版本恢复；
- **上下文体积闸门**：超长命中行裁切至 500 字符、单条超限结果落盘预览、单轮 200,000 字符聚合预算降级落盘、数据文件 Grep 防爆防护；
- **网络与重试策略**：HTTP 400 致命错误一次性失败、408/429/5xx 阶梯重试、本地 Schema 校验失败追加修复提示；
- **推演机制闭环**：Aha 首次自动与再次确认门控、同轮逐字一致冻结前缀、连续两轮无新增早停、无 Chair / 无 R6 的正交机制装配验证；
- **存储与会话**：真实会话与模拟推演物理隔离存储、历史格式平滑迁移、模式过滤与一键清理。

在没有管道子进程权限的环境（如部分受限沙箱）中，可改用进程内测试：

```bash
npm run test:in-process
```
