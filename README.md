# Aha Engine

> 用随机认知算子抽卡，迫使模型离开“最可能的答案”，从不同思维路径寻找问题的关键突破点。

概率预测模型在常规编码、格式转换和知识问答等具有确定标准的任务中表现优秀；但面对开放式创意、机制设计和方案构思，它们很容易收敛到训练语料里出现频率最高的表达，生成平庸、烂大街的套路化答案。多问几次，往往只是得到同一套公式的不同措辞。

Aha 试图解决的就是这种“创意收敛”。它不是让一个模型把方案写得更长、更全面，而是把有限的 token 用在探索更多不寻常但可能有效的思路上：系统为多个独立席位随机抽取不同的认知算子，强制它们改变观察问题的方式；有价值的原子观点进入共享观点板继续碰撞和演化，最后保留一组可追溯的候选思路供人选择。

Aha 更适合回答这些问题：

- 这个问题真正卡住的地方可能是什么？
- 除了行业里反复出现的常规做法，还有哪些突破口？
- 哪个小而关键的机制值得先验证？
- 哪条思路在什么条件下会失效？

它不追求自动生成一份大而全的“完美方案”。Aha 的价值是扩大有效搜索范围，找出能让人产生 Aha moment 的关键点子、因果解释和机制支点，再由人决定往哪条路深入。

当前项目是一个本地优先、可运行的研究原型，自带 Web 工作台、CLI、MCP Server、离线模拟和完整运行审计。运行时只使用 Node.js 内置模块，无需安装 npm 依赖。

## 核心机制：随机算子抽卡

仅仅增加模型数量，并不能自动带来思路多样性；多个模型仍可能一起复述概率最高的套路。Aha 用“认知算子”主动扰动模型的思考路径。

1. Dealer 先判断问题属于哪些领域，从领域特化算子库中挑选最多 8 张真正相关的卡；没有合适卡片时可以不选。
2. 每个席位、每一轮都会从通用算子族和 Dealer 选中的领域卡片中随机抽取 3 张不同的卡。
3. 算子不是抽象的“换个角度想想”，而是带有明确操作步骤和不合格条件的推理任务，例如隐藏前提、因果倒置、关键反例、机制移植、单点支点和二阶效应。
4. 不同席位拿到不同的算子组合，因而沿不同路径寻找关键观点；随机种子让抽卡结果可以复查和复现。

```text
同一个问题
    │
    ▼
Dealer 选择相关领域卡池
    │
    ├── 席位 A：隐藏前提 × 机制移植 × 单点支点
    ├── 席位 B：因果倒置 × 失败倒推 × 二阶效应
    ├── 席位 C：关键反例 × 换问题 × 激励错位
    └── ……每席独立抽取 3 张
                    │
                    ▼
            产生不同的关键思路
```

## 思路如何继续演化

抽卡负责打散思维路径，多轮协作负责让有价值的发现继续生长：

- 同一轮的席位读取相同的冻结快照，彼此看不到当轮尚未汇总的回答，避免发言顺序污染独立探索。
- Dedup 把原子观点按 ADD、MERGE、DROP 合并进公共观点板，减少重复内容继续消耗 token。
- 下一轮读取更新后的观点板，在已有发现上补充、反驳、组合或寻找失效边界。
- 候选思路及其派生关系会被保留；Chair 负责比较和排序，不把所有内容改写成一个虚假的平均共识。
- 请求、响应、抽卡结果、中间快照、耗时、重试和模型用量都可以审计。

完整的五轮协作流程是：

```text
问题与硬约束
  → Dealer 选择领域卡池
  → 各席位随机抽卡并独立寻找关键思路
  → Dedup 更新公共观点板
  → 重复探索与演化 5 轮
  → R6 完善值得保留的候选方向
  → Chair 排序，原始思路与演化路径继续保留
```

固定种子可以复现抽卡结果，并在模型支持时作为生成 seed 传入；远程模型的输出仍不保证逐字一致。

## 快速开始

### 环境要求

- Node.js 22 或更高版本
- 使用真实模型时，需要至少一个兼容模型的 API Key

### 先运行离线演示

离线演示不需要 API Key，也不会发起网络请求：

```bash
npm run demo
```

它会执行一遍固定的模拟流程，并把结果写入 `data/runs/`。模拟内容只用于确认工作流可以运行，不能用于评价方案质量。

### 启动 Web 工作台

```bash
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)，进入“模型与规则”：

1. 在对应模型下输入 API Key。
2. 点击“测试连通性”。
3. 选择各席位及 Dealer、Dedup、Chair 使用的模型，或一键均匀排席。
4. 保存配置，然后回到会议工作台开始运行。

只配置一个模型也可以使用：Aha 会把空缺席位和全局角色自动映射到当前可用模型，同时继续用不同抽卡组合制造思路差异。配置保存在本机，服务只监听回环地址；按 `Ctrl+C` 停止。

也可以通过 `.env` 提供 Key，或直接编辑 `config.local.json` 调整模型接入点、并发、价格和生成参数。这些是高级配置方式，不是首次使用的必经步骤。

## 怎样提出一个好问题

Aha 需要的是一个清晰的创意卡点，而不是让模型代写一份长篇文档。好的输入通常包含：

- 问题：背景事实、目前的关键矛盾，以及你想寻找哪种突破。
- 硬约束：哪些常见答案不要再给，以及想法必须满足的现实边界。
- 实验方案：选择协作深度和对照方式。
- 随机种子与思维刺激：用于控制抽卡结果，并尽量固定实验条件。

例如，不要问“请完整设计一个 AI 编程产品”，可以这样问：

```json
{
  "problem": "一个面向独立开发者的 AI 编程助手功能很多，但用户首次使用后很少在第二周回来。不能更换底层模型，也不能靠增加功能解决。哪个被忽略的关键机制，可能让用户在第一次使用时形成足够明确的价值感？",
  "constraints": [
    "不要输出功能清单或完整产品规划",
    "每条候选思路只聚焦一个关键杠杆，并说清因果链",
    "必须能在一周内用低成本原型验证",
    "必须指出思路成立和失效的条件"
  ],
  "seed": 20260909,
  "experiment": "treatment",
  "use_operators": true
}
```

运行中可以查看每轮原始发言、公共观点板、方案谱系、决策备忘录和技术审计。浏览器刷新或关闭不会停止后台会议；手动停止会取消未完成请求并保留已经生成的内容。

## 四种实验方案

下表按默认 8 个席位、启用思维刺激计算。重试会增加实际调用数。

| 方案 | `experiment` | 用途 | 默认调用数 |
|---|---|---|---:|
| 五轮协作 | `treatment` | 席位逐轮读取共享观点板和候选方向，观察思路演化 | 55 |
| 五轮独立采样 | `independent` | 创意阶段不读取共享成果，和协作组对照 | 55 |
| 单轮多席位 | `single` | 一次并行探索多个候选方向，速度和成本更可控 | 10 |
| 单模型直接回答 | `direct` | 不经过多席位与 Chair，作为基础对照 | 1 |

关闭思维刺激后，前三种方案会各少一次 Dealer 调用。调用次数相同不代表 token、费用或等待时间相同；正式比较应固定问题和模型配置、使用多个种子，并让不知道实验来源的独立评审判断结果。

## 配置模型

日常配置直接在 Web 工作台的“模型与规则”页面完成：输入 API Key、测试连通性、分配席位与角色，然后保存即可。MCP 也有单独的配置 WebUI，见下文。

只有在需要新增服务商、修改接口能力或精细控制并发与价格时，才需要编辑 `config.local.json`。Aha 支持两类接口：

- OpenAI Chat Completions 兼容接口：`protocol` 设为 `chat`，`baseUrl` 填到版本路径，例如 `https://api.example.com/v1`。
- Gemini 原生 `generateContent`：`protocol` 设为 `gemini`，`baseUrl` 应以 `/models` 结尾。

常用字段：

| 字段 | 说明 |
|---|---|
| `models` | 模型名、服务地址、鉴权环境变量及能力声明 |
| `seats` | 创意席位及其首选模型，最多 32 席 |
| `roles.dealer` | 根据问题选择领域思维刺激 |
| `roles.dedup` | 维护公共观点板 |
| `roles.chair` | 对候选思路和方向进行最终排序 |
| `structuredOutput` | `json_schema`、`json_object` 或仅靠提示词约束的 `prompt` |
| `tokenParameter` | 服务实际接受的 `max_tokens` 或 `max_completion_tokens` |
| `maxConcurrent` | 单个模型允许的最大并发请求数 |
| `requestIntervalMs` | 同一模型相邻请求的最小启动间隔 |
| `inputPricePerMillion` / `outputPricePerMillion` | 用于费用估算；未知时保持 `null` |

所有结构化响应都会在本地再次进行结构和业务校验。失败后使用相同请求按固定上限重试，不会暗中更换模型、缩短观点板或修改提示词。

### 代理

模型请求按以下顺序选择代理：

1. `AHA_PROXY_URL`
2. `HTTPS_PROXY` / `HTTP_PROXY`（也支持小写形式）
3. Windows 已启用的系统手动代理
4. 直连

```dotenv
AHA_PROXY_URL=http://127.0.0.1:7890
# AHA_PROXY_URL=direct  # 强制直连
```

支持 HTTP(S) 代理、HTTPS CONNECT 和 `NO_PROXY`；不支持 PAC 与 SOCKS。localhost 请求始终直连。

## CLI

使用 JSON 文件运行真实模型：

```bash
npm run run -- problem.example.json
```

可用的 `experiment` 值为 `treatment`、`independent`、`single` 和 `direct`。追加 `--demo` 可强制使用本地模拟模型。

查看运行诊断：

```bash
node scripts/run-diagnostics.mjs          # 最近一次运行
node scripts/run-diagnostics.mjs --last 5 # 最近五次运行
node scripts/run-diagnostics.mjs --live   # 只看真实模型运行
```

运行自动化测试：

```bash
npm test
```

测试使用本地假服务，不会调用真实模型。

## 作为 MCP 工具使用

`mcp.mjs` 提供一个 stdio MCP Server，可让 Claude Code、Cursor 或其他 MCP Client 把 Aha 作为架构与机制共创工具调用。

先启动 MCP 专用 WebUI：

```bash
npm run mcp:ui
```

打开 [http://127.0.0.1:4318](http://127.0.0.1:4318)。这个页面可以直接：

- 配置并测试各模型的 API Key。
- 调整 MCP 使用的席位和全局角色。
- 复制 Claude Code、Cursor 和 Claude Desktop 的接入配置。
- 用模拟或真实模型试跑，并查看 MCP 运行记录。

如果希望手动接入，通用配置如下：

```json
{
  "mcpServers": {
    "aha": {
      "command": "node",
      "args": ["/absolute/path/to/prototype/mcp.mjs"]
    }
  }
}
```

MCP Server 与两个 WebUI 共用本地模型配置，运行记录也统一保存在 `data/runs/`。调用端应先把问题提炼成关键矛盾、硬约束和简短背景，不要直接灌入整个代码库或大段日志；Aha 的目标是寻找关键突破点，冗长上下文只会被多席位流程成倍放大。

## 数据与审计

每次运行都会写入：

```text
data/runs/<run-id>.json
```

记录包含输入、冻结后的运行配置、算子分配、模型请求与响应、观点板操作、方案谱系、用量、耗时和最终排序。Web 工作台可以导出最终 Markdown 或完整 JSON。

服务重启时，未完成的会议会标记为 `interrupted`。当前没有断点续跑；重新发起会创建一次新的运行，不会暗中续接或改变旧实验条件。

### 密钥与敏感信息

- `.env`、`config.local.json` 和 `data/` 已被 `.gitignore` 排除，请勿手动提交。
- 从 WebUI 输入的 API Key 会保存在本地 `config.local.json`；也可以选择在 `.env` 中提供并由 `apiKeyEnv` 引用。
- 当前原型的运行记录还会冻结完整配置，因此在分享运行 JSON 前必须检查并移除密钥及敏感业务内容。
- 请求内容会发送给你配置的模型服务商；“本地优先”不代表模型推理发生在本机。

## 当前边界

- 同一时间只运行一场会议。
- 多轮协作默认会产生 55 次模型调用，可能需要较长时间并产生明显费用。
- 输出上限、推理档位和随机种子是否被严格执行，取决于具体模型服务。
- 费用是基于配置单价和服务返回 usage 的估算，不处理缓存、阶梯价或批量折扣。
- Chair 排序和引用信息属于模型自报，不等同于客观质量证明。
- 项目提供实验记录与结果对照，但不包含自动 Judge、预算匹配或盲评平台。
